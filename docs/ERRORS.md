# 错误清单（ERRORS）

本项目开发过程中实际遇到并处理过的错误记录。
每条按「症状 → 根因 → 修复 → 验证 → 遗留风险」组织，便于后续维护时对照。

状态标记：✅ 已修复并验证 ｜ ⚠️ 已缓解 ｜ ❌ 已知未修（定时炸弹）

---

## 一、对话链路

### E1 回答卡死、停止按钮按了没反应 ✅

- **症状**：提问后界面一直转圈；点「停止」按钮无任何反应，只能刷新页面。
- **根因**（四个叠加，缺一不可）：
  1. SSE 响应头用了 `Connection: keep-alive`，而 `http.server` 不会自动加
     `Content-Length` 或 `Transfer-Encoding: chunked` → 浏览器**永远等不到流结束**，
     前端 `finally` 不执行，发送中标志永不清除 → 按钮停在「停止」态。
  2. `llm.py` 的 `reset_abort()` 从未被调用 → 一旦 abort 置位，**后续所有请求都被拒绝**。
  3. `abort()` 只置标志位，打不进正在阻塞的 socket 读 → 服务端感知不到取消。
  4. 旧架构是**双请求**（先非流式判断是否 tool_calls，再流式回答）：
     长回答把 45s × 3 重试 ≈ 140s 全部吃满，看起来像死锁。
- **修复**：
  - SSE 改为 `Connection: close`，靠关连接判流结束；
  - 每次请求开头调 `reset_abort()`；
  - `abort()` 里主动 close 当前 HTTP 连接（`_current_resp`）；
  - 合并为**单次流式请求** `_request_stream_events`，同时解析文本增量和 tool_calls 增量；
  - 前端停止按钮做「本地立即解锁」：`currentReader.cancel()` + 状态复位 +
    90s 看门狗兜底（即使服务端没响应也不再卡界面）。
- **验证**：思考中停止 0.01s、输出中停止 0.09s、HTTP 层 0.07s 内中断；正常对话 6.7s 完成。
- **教训**：SSE 在三方框架之外手写时，「浏览器如何判定流结束」必须先想清楚；
  取消机制要覆盖「置位 + 打断 IO」两层。

### E2 调用 save_memory 后整个会话报 400 ✅

- **症状**：记忆保存成功后，下一轮对话直接 400，历史断裂。
- **根因**：`_build_system_prompt()` 在注入长期记忆时**顺手清空了 `agent.messages`**
  （原始实现把整段 prompt 重写并覆盖消息列表），破坏 OpenAI 消息序列的
  assistant(tool_calls) → tool 配对约束，DashScope 直接 400。
- **修复**：`_build_system_prompt` 只替换/重算 system 头，**绝不动历史消息**；
  另加 `_repair_messages()` 在发送前修复孤儿 tool 消息。
- **教训**：「改 system prompt」和「动消息历史」必须严格解耦；任何写历史的操作都要过配对校验。

### E3 切换历史会话后模型"失忆" ✅

- **症状**：在侧边栏切回旧会话，模型完全不记得之前聊过的内容。
- **根因**：`web.py` 的 `get_agent(cid)` 遇到不存在的 cid 就 `Agent()` 新建空实例，
  不会从 `sessions.json` 回灌历史。
- **修复**：新建 Agent 时先把 `sessions.json` 里该 cid 的历史消息载入，再注册工具绑定。
- **验证**：切换会话后提问上下文相关问题，模型能引用之前内容。

## 二、记忆系统

### E4 长期记忆"写了但没存上" ✅

- **症状**：命令行里记住的城市，到 Web 端不存在；Web 端没有任何记忆入口。
- **根因**（三条）：
  1. 命令行只认「记住我常住深圳/北京」这类**正则命令**，其他表述静默丢弃；
  2. LLM 没有 `save_memory` 工具，无法主动记；
  3. Web 端每个会话各自 `Memory()`，`memory.json` 只有最后写的那个会话能落盘。
- **修复**：
  - 新增 `save_memory` / `forget_memory` 工具，系统提示词写明「用户陈述稳定偏好时主动记」；
  - `web.py` 引入**全局单例** `_shared_memory`，所有会话共享；
  - 前端加长期记忆面板（增删查）。
- **验证**：7 项单测 + API 端到端（「常居城市」自动归一化为 `city` 键、自定义键、
  300 字超长被拒、磁盘文件一致）全过。

### E5 memory.json 残留测试数据 ⚠️

- **现象**：`memory.json` 里有两条非测试写入的数据：`city=东莞`、`nickname=鱼`。
- **处理**：判定为真实用户数据，**未清除**，待用户确认后再处理。
- **教训**：自动化测试**不要打生产数据文件**——测试应临时指定独立的 `memory.json` 路径。

## 三、任务与调度

### E6 计划任务"只存不跑" ✅

- **症状**：创建的计划任务存在 `sessions.json` 里，到点不执行。
- **根因**：当时根本没有调度器，任务只是个数据结构（幻想功能）。
- **修复**：新增 `scheduler.py`：后台线程每 30s 检查；
  `parse_schedule` / `parse_reminder_time` / `is_due` / `run_key`；
  daily/weekly 按「日期 + 时间点」去重，interval 按 `last_run` 计算；
  提醒触发走 `reminder_fn` 直接通知（不经过 LLM），任务触发走 `execute_task`
  （独立 `[任务]xxx` 会话跑 LLM，结果落盘并发通知）。
- **验证**：16 项解析单测；E2E 真实跑 LLM 任务 4.3s 出结果并落盘；
  「1 分钟后提醒喝水」5.5s 登记成功、到点通知到达。

### E7 单测里的假阳性 ✅

- **症状**：E2E 脚本偶发断言失败，但服务功能正常。
- **根因**：测试脚本自己的变量 `r` 被循环复用覆盖，**不是服务的 bug**。
- **教训**：排错前先怀疑测试代码；把「服务日志」和「测试日志」分开看。

## 四、联网检索（见 E4 后新增的 web_search 工具）

### E8 本机测试脚本访问 127.0.0.1 返回 502 ✅

- **症状**：服务明明在监听，Python urllib 请求却 502。
- **根因**：urllib 默认读 `http_proxy` 环境变量，把发往 127.0.0.1 的请求也**交给代理**，
  代理自然拒。
- **修复**：测试脚本统一 `urllib.request.build_opener(urllib.request.ProxyHandler({}))`
  显式禁用代理。
- **教训**：本机回环请求永远显式禁用代理；这条后来也写进了 websearch 工具设计假设里。

### E9 360 搜索间歇性返回空页 ✅

- **症状**：同一会话连续多次查询后，结果页没有条目。
- **根因**：360 对短时间多次请求**限流**。
- **修复**：
  - 多引擎轮换：Bing RSS（稳定、直链）→ 360 → Bing HTML；
  - 5 分钟内存缓存同一查询；
  - `_is_antibot()` 识别「安全验证 / 验证码 / 403」并给可读的失败文案。
- **遗留**：免费抓取类搜索没有 SLA，质量有波动，工具在结果首行标注来源与时间，
  让模型和用户对时效有预期。

### E10 360 跳转链接抓不到正文 ✅

- **症状**：用 `fetch_url` 打开 360 结果里的跳转链接，拿不到正文。
- **根因**：360 的跳转页对无特征请求返回空/反爬页。
- **修复**：优先使用 Bing RSS 的**真实直链**；360 结果仅作为兜底来源（摘要即可用），
  `fetch_url` 主要面向直链。

### E11 Bing 对长查询跑偏，且不同查询返回相同结果 ✅

- **症状**：「今天 东莞 限行吗」「2026 春运火车票开售时间」这类查询，
  结果落在天气/黄历/无关专题页；换查询词结果不变。
- **根因**（两个）：
  1. 查询里带「今天/吗/什么时候」等口语词，干扰引擎意图判断；
  2. 只按「是否命中关键词」过滤不够——「2026 年」这种数字词几乎必然命中，
     把真正该命中的核心词（如「火车票」「限行」）挤掉。
- **修复**（三层）：
  - **查询清洗**：剥停用词，「今天 东莞 限行吗」→「东莞 限行」；
  - **核心词过滤**：取最长的非纯数字词作为必须命中的核心词；
  - **两档策略**：严档全落空时退宽松档（命中过半关键词），并在结果首行
    明确标注「相关性一般，必须 fetch_url 核实」；
  - **查询收敛**：相关性不足且关键词 >2 时，自动用前两个关键词重搜一次并注明。
- **教训**：给 LLM 用的检索工具，「宁缺毋滥 + 明示置信度」比「尽量多给结果」重要——
  垃圾结果会被模型当真。

### E12 PowerShell 重定向输出是乱码 ✅（环境层）

- **症状**：`... | Out-File x.txt` 再读出来，中文全是方块或问号。
- **根因**：Windows PowerShell 5.1 的 `Out-File` 默认 UTF-16 LE（带 BOM）或系统 ANSI。
- **修复**：统一 `Get-Content -Encoding Unicode | Out-File -Encoding utf8` 转一道，
  或干脆脚本里自己写 UTF-8 文件。
- **教训**：在本机，「命令输出 → 文件 → Read 工具」是标准排障路径，但**编码必须 UTF-8 闭环**。

## 五、服务进程与环境

### E13 改了代码重启服务却不生效 ✅

- **症状**：确认改了代码、也"重启"了服务，行为却和旧代码一样。
- **根因**：Windows 上 `http.server` 的 `allow_reuse_address` 允许**多个进程同时绑 8000**；
  旧进程没被真正杀掉，请求被随机分发到新旧进程。
- **修复**：重启前 `netstat -ano | findstr :8000` 找到**所有**监听 PID，
  `Stop-Process -Id <pid> -Force` 逐个杀，再启动并复查监听。
- **教训**：「重启成功」的唯一证据是「只有一个新 PID 在监听」，不是启动命令返回 0。

### E14 Start-Process 带 -RedirectStandardOutput 启动的服务静默死亡 ✅

- **症状**：`Start-Process ... -RedirectStandardOutput x.txt` 起的服务，几秒内消失，无日志。
- **根因**：该参数在目标进程退出/异常时会把错误吞掉（具体触发条件未完全查明）。
- **修复**：服务一律用「后台任务 + 前台运行 + `Out-File`」的方式起，日志可读、存活可查。

### E15 PowerShell 工具吞输出 ✅（环境层）

- **症状**：命令 exit 0，但 stdout 完全为空（连 `Write-Output "test"` 都无回显）。
- **结论**：git/服务状态排查一律用 Bash 工具；PowerShell 只用于杀进程等「不需要读输出」的操作。

### E16 Bash shim 缺 coreutils ✅（环境层）

- **症状**：`head` `tail` `dirname` `cat` 等报 command not found。
- **修复**：每条命令前显式补 PATH：
  `export PATH="...PortableGit/.../usr/bin:.../mingw64/bin:/c/Windows/System32:$PATH"`；
  且**每个 Bash 调用都要补**（shell 状态不跨调用保留）。

## 六、GitHub 推送（2026-11-14）

### E17 git push 反复 `CONNECT tunnel failed, response 502` ✅

- **根因**：本机代理（127.0.0.1:50340）拦截 `CONNECT github.com:443`（实测超时/502），
  而 `api.github.com`、`codeload`、`ssh.github.com:443` 是通的。**不要整体判定"网络不通"**。
- **修复**：改用 REST API 手工构造 blob → tree → commit → ref 推送，
  并保持远程 commit SHA 与本地 HEAD 一致（无分叉）。详见 `docs/DEBUGGING.md` 末节。

### E18 SSH over 443 握手卡死 ✅（已放弃该路径）

- **症状**：隧道建立成功，但服务端 banner 异常（`remote software version 11529790`，
  非 GitHub 的 `babeld-*`），发完 KEXINIT 后永久无响应。
- **结论**：中间设备干扰，SSH 兜底不可用；验证不通就不要再纠缠，直接换 API 路径。

### E19 API 推送的四个坑 ✅

| 坑 | 现象 | 处理 |
|---|---|---|
| 空仓库建 blob | 409 `Git Repository is empty` | 先 `PUT /contents/.bootstrap` 造占位提交，最后覆盖 ref |
| 中文路径 | `git ls-tree` 把路径转义成 `"agent/LLM_\350..."` 导致解析崩 | `git -c core.quotepath=false ls-tree -r HEAD` |
| commit date 格式 | `"1794649398 +0800"` 返回 422 | 转 ISO 8601，偏移一致才能保住 SHA |
| `git update-ref` | 返回 0 但 ref 没写入，status 显示 `[gone]` | 直接写 `.git/refs/remotes/origin/main` 文件兜底 |

- **位置**：`agent/tools/local_utils.py`
- **风险**：节日日期表硬编码 2026，跨年后计算结果错误（且不会报错，是**静默错误**）。

- **建议**：内置规则标注「最后核实日期」，超过 N 天自动降级为联网查询。
