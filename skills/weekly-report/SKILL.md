# 周报生成 Skill（weekly-report）

## 目标

帮用户把口语化、零散的本周记录，整理成一份结构清晰、重点突出、可以直接发出去的周报。

## 输入约定

从用户输入中抽取：
- **素材**：用户口述或粘贴的本周事项（可以有缺漏、顺序混乱、口语化）。
- **受众**：领导 / 团队 / 自己存档（默认领导，语气更凝练）。
- **风格**：简洁版（默认）/ 详细版。

素材不足时不要编造。缺关键信息（比如用户只说「帮我写周报」但一件事都没提），先问一句：
「这周你主要做了哪几件事？想到哪说哪，我来帮你整理。」

## 工作流（SOP）

1. **收集素材**：用户给了素材就用；没给就追问一轮，追问后仍没有具体事项则不生成，直接说明。
2. **归类**：把事项归入四类——本周完成 / 进行中 / 下周计划 / 风险与求助。
   归不进去的放进「其他」。
3. **润色**：每条事项改写为「动词开头 + 可衡量结果」的一句话，
   例如「聊了客户」→「完成 3 家客户需求沟通，确认 2 个进入报价阶段」。
   不得虚构数字与结果——用户没说的量化信息就保持定性描述。
4. **排版**：用 Markdown 输出，模板见 `references/template.md`
   （用 read_skill_file 读取，风格为简洁版时用模板的「简洁版」部分）。
5. **收尾**：输出后问一句「需要调整语气（更正式/更口语）或改成详细版吗？」

## 约束规则

- 严禁编造用户没提供的事项、数据和结果。
- 条目数量：每类不超过 5 条，超过则合并同类项。
- 风险与求助类要用中性陈述，不带情绪、不甩锅。
- 输出全程使用简体中文（用户明确要求英文除外）。

## Few-Shot 示例

**用户**：「帮我写周报，这周主要弄了支付接口联调，还有俩 bug 修了，下周要搞对账模块」
**回答**：
> ## 本周工作周报
> **本周完成**
> - 完成支付接口联调，打通下单到回调全链路
> - 修复线上 bug 2 个（已随本周版本发布）
>
> **进行中**
> - 无
>
> **下周计划**
> - 启动对账模块开发
>
> 需要调整语气或改成详细版吗？
